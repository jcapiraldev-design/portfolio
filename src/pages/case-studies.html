Case study 02

PHP 8.4 upgrade and security hardening for two legacy sites

PHP 8.4, Fegg framework, SQLite, PHPCompatibility, Git

  • 2legacy sites upgraded
  • ~190pages tested on one site
  • 0password resets needed
Problem
Two websites for a Japanese welfare organization, a corporate and recruitment site and an internal file portal, had to move to PHP 8.4. Several admin screens and upload forms crashed with fatal errors, and the login still used outdated sha1 password hashing.
What I did
Scanned both codebases with PHPCompatibility, then ran each site locally and tested every page, contact and recruitment form, and CMS screen. Fixed PHP 8 errors in the admin and upload code, replaced deprecated functions, removed an outdated library, tightened server access rules, and moved logins to password_hash() with an automatic upgrade for existing users.
Result
Both sites run on PHP 8.4 with their existing behavior intact, and admin accounts use modern password hashing without anyone having to reset their password.

Case study 03

Bringing a legacy PHP framework back to life on PHP 8.4

PHP 8.4, Fegg framework, SQLite, PHPCompatibility, Git

  • 73 / 73templates identical
  • 0errors, warnings, or deprecations
  • 100%pages, CMS screens, and forms
Problem
A Japanese company's corporate and recruitment website returned a fatal error on every page under PHP 8. Its template engine was built on create_function(), which PHP 8 removed, and local testing also showed dozens of deprecation warnings that broke sessions.
What I did
Rewrote the template compiler's dynamic functions as native closures, then proved they behave exactly the same by rendering the full site with the old and new logic and comparing the output. Fixed PHP 8 errors in the CMS, file uploads and the job application form, and cleared every deprecation warning by declaring each class property explicitly, without falling back on #[\AllowDynamicProperties] to silence them. I also repaired a broken gallery uploader and tightened server access rules.
Result
Every page, CMS screen and form runs on PHP 8.4. All 73 compiled templates came out identical to the original, and a full test run with every warning switched on produced zero errors, warnings or deprecations.
